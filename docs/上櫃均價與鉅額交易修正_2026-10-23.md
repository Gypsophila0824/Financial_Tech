# 上櫃均價與鉅額交易修正（2026-10-23）

上櫃資料改用櫃買完整行情 `afterTrading/dailyQuotes`，並扣除 `blockTrade/tradeInfo` 的當日單一證券鉅額交易股數與金額。先前使用的 `afterTrading/otc` 統計範圍不同，不能直接重現此次平台均價。

```
結算均價＝（完整成交金額－當日單一證券鉅額成交金額）
        ÷（完整成交股數－當日單一證券鉅額成交股數）
```

此規則以使用者提供的 2026/10/22 六檔上櫃成交截圖驗證，並非主辦方正式規則已獲確認。範圍版本為 `tpex_daily_ex_single_block_v1`；未另扣股票組合鉅額交易。

## 證據與計算精度

萬潤完整金額 2,672,874,685 元、股數 2,038,480 股；單一證券鉅額 19,987,500 元、15,000 股。

```
(2,672,874,685 - 19,987,500) / (2,038,480 - 15,000)
= 1,311.051843…
```

四位均價為 1,311.0518，兩位顯示為平台的 1,311.05。其餘五檔當天單一證券鉅額交易報表無紀錄，完整行情均價取兩位後分別為富喬 147.01、聯亞 2477.43、環宇-KY 431.08、台燿 1518.19、群聯 1909.50，也均與平台截圖相符。

正式結算保留原本四位均價及逐筆手續費捨去規則，未因顯示價一致就改成兩位計算。D-Plan 委託股數仍按前日收盤價推導，沒有改成成交均價。

## API 與資料核對

- 完整行情：`https://www.tpex.org.tw/www/zh-tw/afterTrading/dailyQuotes?date=2026/10/22&id=&response=json`。
- 鉅額交易：`https://www.tpex.org.tw/www/zh-tw/blockTrade/tradeInfo?date=2026&code=&id=&response=json`。
- 鉅額 API 查全年；依每筆「成交日期」篩選目標交易日。該欄位可能是數字 `1151022`，頂層 `date` 則是年度起日，不能拿頂層日期判斷當日紀錄。
- 同一交易日、同一股票可能有多筆配對／逐筆交易，需全部加總後扣除。年度資料在單次執行內共用，減少查詢次數。
- 檢查 API 狀態、日期、必要欄位、總筆數、數值及扣除結果。查詢失敗不等於零筆交易；失敗時不能產生這個範圍的結算均價。
- `daily.csv` 的 `volume/value` 為扣除後的股數／金額，另存 `total_volume/total_value`、`block_volume/block_value`、`block_source` 和 `price_scope` 作對帳。
- OpenAPI、MIS、FinMind 仍可作行情備援，但未具備上述範圍驗證的均價不得用於結算。

## 更新舊行情

既有 CSV 沒有此範圍標記的上櫃資料會標記為需要重抓；`--skip-fetch` 不能繞過結算的範圍檢查。可在收盤資料公布後只更新指定一天：

```powershell
Set-Location 'C:\Users\Josep\projects\Financial_Tech'
.\.venv\Scripts\python.exe -X utf8 -m src.agent.datafeed.market --date 2026-10-22
```

這個指令只替換指定日期的行情，不修改帳本、成交委託、其他日期的價格。若需完整回測，仍須更新回測期間的舊上櫃行情；原本 `--days 80` 流程會重抓遇到的舊範圍資料。

## cash_check

對話工作區的 `outputs/check_settlement_cash.py` 同步使用新範圍並保留原始金額、股數與鉅額扣除資料；預設四位計算。指定 `--price-decimals 2` 可重現先前「cash_check 四位均價再四捨五入兩位」的情境，並非主張平台內部只用兩位計價。

```
--fetch --price-decimals 2
```

實際期初現金及 D-Plan 檔案仍須由使用者提供。這次改動只修正上櫃行情範圍，未確認先前約 6.75 萬元的剩餘現金差額來源，也未調整手續費率、稅率或帳本核對門檻。
