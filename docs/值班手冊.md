# 值班手冊（初賽 10/27～11/27，共 24 個交易日）

## 先記住三條紅線

1. **只能決定「過」或「退回重跑」，絕對不能手改 D-Plan 的任何內容。**
   簡章六(一)：投資決策須由 AI Agent 自主產生；手改屬於「決策與交易行為不一致」，可被直接取消資格。
2. **繳交時窗：交易日前一日（日曆日）19:30 ～ 交易日 08:55。** 超過就算未繳交，記警告一次。
   **首次繳交是 10/26 19:30～10/27 08:55，交的是 10/27 的 D-Plan；10/26 休市，沒有 D-Plan**（Slack 答覆）。
3. **同一天重跑多次，必須繳交最後一次產生的檔案**，不可以從幾份裡面挑（Slack 答覆）。檔名固定，重跑會直接覆蓋。

警告累積 3 次取消資格；24 天至少要成功繳交 22 天才列入排名。
Active Share 連續 2 天低於 15% 會被直接取消資格，沒有警告緩衝。

## 每日流程

| 時間 | 動作 |
|---|---|
| 前一交易日收盤後 | 主辦方 19:00 更新淨值 → 執行 `live settle` 結算帳本並與後台核對 |
| 前一日 19:30 起 | 繳交時窗開啟，執行 `live run`（三大法人資料公布後才有完整資料） |
| 交易日 08:30 前 | 完成審核與繳交（保留重跑時間） |
| 交易日 08:55 | 繳交截止 |

建議在前一天晚上 19:30～22:00 之間完成，早上只留給出狀況時重跑。

### 1. 結算前一交易日的帳本（每天收盤、19:00 後）

```
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live settle --trade-date <剛結束的交易日> --team-id TEAM_11161
```

程式依當日成交均價、手續費、證交稅結算 `data/state/ledger.json`。畫面列出的持股、現金、NAV 和後台「庫存明細」逐項比對：
- **一致** → 完成。
- **不一致** → 以主辦方為準修正 `data/state/ledger.json`（修正系統資料，不是介入決策），並在群組回報差異。

### 2. 產生 D-Plan

```
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live run --trade-date <交易日> --team-id TEAM_11161
```

程式依序：檢查交易日與時窗 → 抓資料（行情與三大法人、主動型 ETF 持股、基本面、新聞）→ 確認前一交易日收盤資料已到 →
**自動核對帳本**（依前一天的帳本＋委託推算，股數不符就停止）→ 列出帳本。
再看一次帳本與後台一致後，加上 `--reconciled`（資料剛抓過可加 `--skip-fetch`）：

```
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live run --trade-date <交易日> --team-id TEAM_11161 --reconciled --skip-fetch
```

### 3. 審核

看畫面最後的結論，並打開 `output/live/review_TEAM_11161_<日期>.md`：
- **「可送審」** → 看「注意」項目（WARN）與「程式自動調整與提醒」，沒有異常就繳交 `output/live/D-Plan_TEAM_11161_<日期>.json`。
- **「不得提交」** → 不要繳交，依下方「出狀況怎麼辦」處理後重跑。

每次執行的完整輸出都存在 `logs/`。

## 出狀況怎麼辦

| 狀況 | 處理方式 |
|---|---|
| 合規檢查有 REJECT | 不可繳交。重跑一次；同一項目仍失敗，截圖貼到群組通知負責寫程式的人修程式（不是改 D-Plan）。 |
| 「行情資料尚未包含前一交易日」 | 收盤或三大法人資料還沒公布，稍後再跑（建議 19:30 以後）。 |
| 帳本核對未通過（股數不符） | 對照後台「庫存明細」修正 `data/state/ledger.json`。若後台數字與帳本相同、差異是委託未成交等原因，加 `--confirm-ledger` 記錄確認後再跑。 |
| 櫃買中心連不上 | 程式會依序改用櫃買 OpenAPI、證交所 MIS、FinMind 備援並在 D-Plan 標明來源，不需處理。 |
| 主動型 ETF 持股抓不到 | 程式沿用最近一份持股並在「資料來源」標 WARN，可繳交但在群組回報；完全沒有持股檔時合規檢查會 REJECT，通知負責寫程式的人。 |
| 新聞抓不到、或 LLM 錯誤、沒有金鑰 | 程式照常產出：新聞視為中性、推論改用程式範本（Slack 答覆：規則式 Agent 亦合規）。審核摘要會列出，可繳交，但在群組回報。 |
| Active Share 出現 ❗（低於 15%） | 仍要繳交（不交會記警告），立刻在群組回報；隔天必須回升，連續 2 天低於 15% 會被取消資格。 |
| 值班人臨時無法執行 | 立刻通知候補值班人。08:55 前務必有人繳交。 |
| 08:55 前來不及產生合格的 D-Plan | 寧可不交，也不要交不合規或手改過的檔案（不交記一次警告；手改可能被直接取消資格）。 |

## 每週工作
- 檢查警告次數、Active Share 最低值（審核摘要「前 15 大／Active Share 最低 3 檔」），有疑慮在群組提出。
- 確認 `logs/` 沒有重複出現的資料來源警告。
