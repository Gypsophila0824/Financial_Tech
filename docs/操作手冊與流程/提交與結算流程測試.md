## 範圍與安全邊界

測試位於 `tests/test_submission_settlement.py`，沿用 pytest。
使用合成行情、平台證據與暫存帳本，執行實際的提交封存、版本選擇、
結算與對帳函式；行情供應器、時鐘及檔案根目錄替換為測試環境。
禁止外部資料抓取，不呼叫付費模型、不提交交易、不修改正式帳本。

回執仍由值班人核實。本地雜湊只能偵測檔案相對封存紀錄的變更，
不能驗證平台回執真偽、偵測未登錄的最新提交，亦非防竄改的外部簽章。

## 涵蓋情境

- 依平台提交時間選版，不依本地產生或登錄順序。
- 未提交版本不參與結算；封存或回執修改即停止。
- 本地檢查未過、空回執、重複提交時間不得登錄。
- 官方日期、隊伍、股數、現金或 NAV 不符時，帳本保持原樣。
- 無交易仍更新收盤市值、NAV 與結算日期。
- 成功提交但交易無效時保留原委託，只更新原持倉估值。
- 無效處理缺少提交、狀態、原因或證據時拒絕。
- 重複結算不得再次扣款。
- 缺少均價、缺少收盤價不得假造估值；NaN、零、負數及無限大均價被拒絕。
- 正式回測遇到缺少委託均價時停止。

## 官方判定當日交易無效的操作

先登錄成功提交版本，再取得官方當日庫存、現金、NAV 與交易無效通知。
在本地官方資料轉錄 JSON 中附加 `"trade_status": "invalidated"`。
這是本系統的轉錄欄位，**不是聲稱平台原生具有此欄位**。

執行格式（路徑與日期須換成實際資料）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live settle --trade-date YYYY-MM-DD --team-id YOUR_TEAM --official-state PATH_TO_OFFICIAL_JSON --receipt-file PATH_TO_OFFICIAL_EVIDENCE --invalidated --reason "官方通知當日交易無效，已核對"
```

- `--invalidated` 與 `--no-trades` 互斥。
- 必須具備成功提交紀錄、非空證據、狀態與原因；仍須通過官方帳本對帳。
- 結算稽核保留 `submitted_orders`，實際 `orders` 為空，
  並記錄 `settlement_status=invalidated` 與原因。
- 不刪除成功提交紀錄，不把交易無效改稱未提交，也不推定免除警告或其他競賽處分。
- 本入口只處理當日全部交易無效，不支援人工挑選部分委託取消。
