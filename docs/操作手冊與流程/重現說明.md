# Agent 重現說明

本文件說明如何以 D-Plan 中記錄的 `agent_metadata.code_version`，重現當日 Agent 的決策與委託。

## 版本識別與程式碼留存

- `code_version` 格式為 `pkg:<12 碼雜湊>`，由以下內容的 SHA-256 計算：`config/` 設定、`src/` 全部程式碼（含策略參數 `src/agent/strategy.py`
  與 LLM 提示詞）、股票主檔 `data/security_master.csv`、`requirements.txt`，以及 `rules.SCHEMA_RELATIVE_PATH` 指向的當前官方 schema。2026-10-22 更新後使用 `比賽文件/官方更新_v4.3_2026-10-22/D-Plan.schema_v4.3.json`；歷史 v4.2 封存仍以當時的程式與 schema 重現，不得混用新版本。
  任何參數或提示詞變動都會產生新的版本識別。
- 每個版本第一次執行時，上述檔案自動打包為 `output/code_archive/pkg_<雜湊>.zip`。

## 每日輸入包

正式模式每次在 `output/live/runs/<run_id>/` 產生 D-Plan 時，同時保存 `inputs_<team_id>_<交易日>.json`，內容包括：
- 150 檔的量價因子（A1～A4 與分數、60 日波動率）、基本面因子（B1～B4 與分數）、前日收盤價與可交易清單；
- 新聞分數（每檔主角新聞則數、最嚴重利空、最好利多、引用新聞）與全部資料來源；
- 交易前帳本（持股、現金、前日淨值）與各主動型 ETF 實際公布的前 15 大持股；
- 當日 D-Plan 的決策（標的、動作、目標權重）、不動持股與委託。

外部資料事後可能修正、LLM 生成的文字每次不同，因此重現的驗證標準為：
**同一版本程式＋同一份輸入包 → 決策與委託逐筆相同。** 推論文字（LLM 改寫）不在比對範圍。
LLM 的新聞判讀與推論改寫另以快取保存（`data/news/labels.jsonl`、`summaries.jsonl`、`data/narratives/cache.jsonl`），
同一份輸入重跑直接沿用，不重新呼叫 LLM。

原始資料另存於 `data/market/`（行情、三大法人累積檔）、`data/fundamental/<日期>/`（月營收、營益分析、財報原始回應）、
`data/etf/`（主動型 ETF 持股）與 `data/news/`（新聞清單、判讀結果、Wayback 存檔紀錄）。

## 重現步驟

1. 取出對應版本程式碼：解壓 `output/code_archive/pkg_<雜湊>.zip` 到新資料夾。
2. 建立環境（Python 3.12）：
   ```
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
3. 將該日輸入包複製到資料夾內，執行：
   ```
   .\.venv\Scripts\python.exe -X utf8 -m src.agent.reproduce inputs_<team_id>_<交易日>.json
   ```
4. 程式會先比對版本；**`code_version` 不一致時只列警告，仍會繼續執行**。原版重現驗收須自行先還原相同版本，不能把不同版本下相同結果當作原版證據。程式用 mock 模式與範本推論重算，逐項列出
   決策、不動持股、委託是否相同，最後顯示「重現成功」或「重現失敗」。

## 決策流程摘要

官方行情、三大法人、基本面、主動型 ETF 持股、新聞、市值快照 → 150 檔評分（量價 50%、基本面 35%〔營收成長／加速各 50%〕、新聞 10%、上市市值前 20 名 5%；市值名次第 1 名 2.00、第 2 名 1.50、第 3 名 1.00、第 4–5 名 0.80、第 6–10 名 0.65、第 11–20 名 0.55，其餘 0.50）
→ 重大利空否決 → 前 25 名、權重 ∝（總分 − 0.5）÷ 60 日波動率、單檔上限、Active Share 控制（目標 ≥ 30%）
→ 換股緩衝（現行正式線前 50 名續抱；研究投組與舊結果須依各自 manifest 還原）、不交易區間 3%、現金回補與下限 → 官方公式計算委託股數（程式計算，不經 LLM）
→ 由委託淨流向決定 posture → 推論文字（範本，可由 LLM 改寫、經數字與用詞檢查）→ 合規檢查（schema、引用鏈、
六(十四) 警告規則、Active Share）。


## 封存邊界與回測重播

輸入包另含 active_share_rule、strategy_manifest、逐檔 etf_dates 與帳本風險歷史。股票主檔仍由還原版本的 data/security_master.csv 讀入，須一起還原。文字、完整 D-Plan 位元內容與平台結算不在 reproduce 比對範圍。

實際提交稽核須使用 output/live/submissions/<team>/<日期>/<event_id>/ 的輸入包、D-Plan、回執；不能只看 runs 最後產物。雜湊是本地一致性檢查，不是外部不可竄改存證。

離線回測完整重播使用另一入口：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.backtest.runner --replay output/backtest/ORIGINAL_RUN --out-dir output/backtest/NEW_REPLAY_RUN
```

輸出須為新目錄；驗證封存及比對回測結果，不產生正式 D-Plan 或提交交易。詳見回測股利與封存說明及架構修正與驗收文件。
