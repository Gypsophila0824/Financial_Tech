# 值班手冊

更新：2026-10-17；依 live.py、submissions.py、settlement_transaction.py、compliance.py 核對。

## 使用狀態

目前 `config/official_policy.json` 的 `formal_release_approved=false` 且 pending 未清空，`live run` 和每日管線的 live 模式會停止。下列流程供完成驗收後使用。不得只切換旗標繞過待辦；程式要求 pending 清空、核准為 true，並提供含 official_sources、reviewer、reviewed_at、validation_report 的 approval_evidence。正式股利／公司事件帳本、平台均價與費稅精度等仍待完成，測試通過不能取代平台驗收。

## 操作原則

- 人員只審核通過或退回修程式重跑，不得手改 D-Plan。依既有官方問答，同日重跑須提交最後一次產生版本，不得挑選交易內容。
- 時窗為交易日前一日曆日 19:30 至交易日 08:55（台灣時間）。依專案保存的 Slack 答覆，首次為 10/26 19:30～10/27 08:55；仍以主辦方最新公告為準。
- 每次執行存入 `output/live/runs/<run_id>/`，檔名固定、目錄獨立，不覆寫其他次執行。
- 平台由人員手動上傳，本地程式不自動提交或驗證回執真偽。產生檔案不等於提交成功。
- 結算依「已登錄的最後成功平台提交時間」選版，需完整登錄所有成功提交，不能以最後產生檔案推定成交。

指令在專案根目錄執行，先依 requirements.txt 建立 .venv。YYYY-MM-DD、RUN_ID 及證據路徑均須替換。

## 1. 產生交易日 T 的 D-Plan

有持股時須先完成 T-1 結算；首日無持股使用初始帳本，不需虛構前日提交。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live run --trade-date YYYY-MM-DD --team-id TEAM_11161
```

流程：核准、交易日與時窗檢查 → 抓行情／法人、ETF、基本面、新聞 → 確認前交易日資料 → 帳本核對。未加 --reconciled 時印出帳本後停止。確認持股、現金及 NAV 與官方後台一致，再執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live run --trade-date YYYY-MM-DD --team-id TEAM_11161 --reconciled --skip-fetch
```

--skip-fetch 只在資料已完整時使用。--confirm-ledger 可記錄核對差異的確認，不是免除對帳；先查明並保留證據。有持股且帳本日期不是前交易日仍會停止。

## 2. 審核與手動提交

使用畫面顯示的同一次執行目錄，包含：

```text
output/live/runs/<run_id>/
  D-Plan_TEAM_11161_<T>.json
  inputs_TEAM_11161_<T>.json
  review_TEAM_11161_<T>.md
  run_record.json
```

合規報告與策略 manifest 也在該目錄；run_record.json 記錄檢查結果及 D-Plan／輸入包雜湊。完整紀錄在 logs/。

有 REJECT 不得提交，回到程式或資料管線修正後重跑；只有 WARN 時須閱讀原因。通過後於時窗內手動上傳該次 D-Plan，保存平台回執及含時區的成功時間。

## 3. 登錄成功提交

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live confirm-submission --trade-date YYYY-MM-DD --team-id TEAM_11161 --run-dir output/live/runs/RUN_ID --receipt-file evidence/submission_receipt.bin --submitted-at "YYYY-MM-DDT20:00:00+08:00" --confirmed
```

--confirmed 表示人員已核實回執對應該檔案。程式檢查身份、時窗、通過狀態及雜湊，複製至 `output/live/submissions/<team>/<T>/<event_id>/`。每次成功重交都須登錄；本地無法發現未登錄的較晚提交。結算後不可補登該日提交。

## 4. 收盤後結算 T

取得平台當日結算證據，準備本地轉錄 JSON（不宣稱是平台原生格式）：

```json
{
  "team_id": "TEAM_11161",
  "as_of": "YYYY-MM-DD",
  "holdings": {"2330": 1000},
  "cash": 100000000,
  "nav": 1000000000
}
```

以上數字僅示意欄位，必須替換為官方實際數字。股數須為非負整數，現金非負且有限，NAV 為正且有限。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live settle --trade-date YYYY-MM-DD --team-id TEAM_11161 --official-state evidence/official_state.json --receipt-file evidence/settlement_receipt.bin
```

程式核對提交前帳本，依最後成功提交版本計算成交，檢查有效均價與當日收盤價，取得 ETF 資料並保存逐檔 Active Share 觀測。官方股數須完全一致，現金與 NAV 各差異不得超過 1 元，否則停止寫入。須查明提交、成交、費稅或公司事件差異並保留證據，不能以手改帳本代替尚未完成的正式事件帳務驗收。

須依交易日順序結算，不可重複或倒序。帳本在 data/state/ledger.json；證據與稽核在 data/state/history/。

### 無交易與交易無效

- 未提交／拒收且已核實無交易：上述命令加 `--no-trades --reason "實際原因"`，仍需官方資料與證據；已有成功提交紀錄會拒絕。
- 成功提交但官方判定全部交易無效：先登錄提交，官方轉錄 JSON 加 `"trade_status": "invalidated"`，結算加 `--invalidated --reason "官方原因"`。保留 submitted_orders，實際 orders 為空，更新原持倉估值。
- 兩旗標互斥；不支援人工取消部分委託，不表示免除競賽處分。詳見 [提交與結算流程測試](提交與結算流程測試.md)。

### 結算中斷恢復

如當日已建立 journal，執行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.agent.live recover --trade-date YYYY-MM-DD --team-id TEAM_11161
```

恢復使用封存前後帳本與證據，不重算交易或費用；現有帳本既非前態亦非後態會停止。沒有 journal 的舊中斷不能使用此方式。settlement.lock 檔案保留是正常行為，程序結束由作業系統釋放鎖，不應刪檔繞過執行中的程序。

## 異常處理

| 狀況 | 處理 |
|---|---|
| 正式使用未核准 | 完成 policy 待辦與驗收，保留 gate。 |
| 必要行情、ETF 或基本面抓取失敗 | live run 停止，修資料管線後重跑；新聞抓取失敗可警告後繼續。 |
| LLM 無金鑰或失敗 | 使用範本推論與中性新聞等 fallback，仍需其他檢查通過。 |
| ETF 舊資料或不完整 | 舊資料有時點警告；官方 30 檔、日期或完整性不符會 REJECT，不能一概視為可提交。 |
| Active Share 單日預估低於 15% | WARN 並優先處理，不代表官方單日豁免。 |
| 前日觀測與今日預估連續偏低 | 內部保護會 REJECT，須處理並重跑；本地觀測不是官方裁定。 |
| 結算數字不符或價格缺漏 | 停止寫入，查明官方證據與資料，不猜均價或用舊價冒充當日收盤。 |
| 值班人缺席 | 通知候補，依時窗完成並保存操作及提交證據。 |

每日檢視警告、Active Share 逐檔資料日期與偏低紀錄、被動超限天數、提交及結算是否齊全。本地可送審不是主辦方接受保證。
